# План: адаптация DS под Angular (свой npm-пакет)

Статус: решение принято ~10.09.2026, детали — на созвоне с разработчиком (ориентир 14–15.09.2026).

## Контекст

- В компании живёт **NGX Spacebridge** (`@ngx-spacebridge/cdk` + addons) — внутренняя Angular-библиотека поверх Angular Material + ngx-toastr, со своей докой (CDK, Directives, Pipes, Services, Storage, Core, Grafana). Почти все прод-проекты полагаются на её стили и компоненты.
- Вливать наши стили туда напрямую нельзя: проекты **nms app host** и **estella** часто переопределяют цвета (в т.ч. тёмную тему) и ведут «своё видение» — перенос новых стилей туда ломается об это.

## Решение

- Делаем **свой npm-пакет** со стилями DS (токены + компонентные CSS), не воюем с ngx-spacebridge.
- Позиционирование (со слов разраба): наша DS — «новое полотно» с новым дизайном **для будущих проектов**; существующие проекты не трогаем.
- Путь внедрения: сначала токены+CSS (подключение через `angular.json` → `styles`), потом тонкие Angular-обёртки над нашей разметкой по мере надобности. DOM-фабрики `sbMk*` напрямую не переносятся.

## Риски / заметки

- Главный организационный риск — команды-«персонажи», игнорирующие библиотеку и стили (цитата разраба). Аргументация нужна на созвоне: что есть, как воплотить, как обосновать.
- Наш козырь против их боли с переопределениями: темизация у нас токенами из Figma, светлая/тёмная — из коробки, а не патчами поверх.

## Дистрибуция (работает с 10.09.2026)

GitHub Release `v1.15.0` с tarball'ом; установка без registry:
`npm i https://github.com/susheme/Spacebridge-DS/releases/download/v1.15.0/spacebridge-ds-styles-1.15.0.tgz`.
Tarball собирается: `cp -R pkg package && tar -czf spacebridge-ds-styles-<ver>.tgz package`.
Обновления команда подтягивает сменой ссылки (npm update по URL не работает).
`npm i` на машине разработчика ещё не проверялся — первый живой прогон покажет.
