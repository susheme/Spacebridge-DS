# План: dogfood хедеров в хроме DS

> Инициатива переезда хром-обвязки DS (страницы компонентов, exampleBox-toolbar, секции) на собственные Header L / M / Section вместо ad-hoc <h1>/<h3>

Затащить собственные Header L / M / Section в GUI самого DS (не только как demo-разметку в их секциях). На текущий момент (2026-05-06) только `Section Header` реально используется — в `js/core.js:140` для NAV. Остальные хедеры висят мёртвым грузом.

**Кандидаты:**
- **Header L** — заголовок страницы компонента (вместо `<h1>` + description). Поверх можно повесить status badge «Done/WIP», More-меню «Copy link / Open in Figma».
- **Header M** — топ-бар `exampleBox` (там уже есть Copy/Download toolbar — идеальный inline+more кейс).
- **Header Section** — заголовки секций внутри страницы компонента (вместо `<h3>` + desc).

**Why:** dogfooding ловит баги в хедерах на реальных кейсах (как было с overflow:hidden клиппингом dropdown'а), валидирует API на не-демо использовании, делает DS визуально консистентным.

**How to apply:** НЕ начинать как локальную замену `<h1>` — это полноценный редизайн страницы. Нужно проработать: вертикальный ритм Header → desc → exampleBox, paddings/gaps по 8/16/24-сетке, спейсинг между секциями, sticky-поведение (Header S умеет sticky), responsive на узких ширинах. Делать **отдельным заходом**, не вперемешку с багфиксами компонентов. Coupling с хромом DS растёт, но поломки сразу видны — это плюс.
