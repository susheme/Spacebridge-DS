> Все границы (border, border-bottom, outline и т.п.) в DS используют токен `--border`, не `--surface-2`. Surface-токены — для фоновых поверхностей (--surface-1/-2/-3), не для границ. В dark theme --surface-2 почти невидим (#0F151E), а --border контрастен в обоих темах (#BFC5D2 light /

# Правило

Для **любого border/stroke/outline** в компонентах DS использовать `var(--border)`, **не** `var(--surface-2)`.

# Why

Юзер 2026-05-20: «Сорян мой косяк. Давай отныне везде где есть бордер/строук будем юзать --border (возможно позже добавим еще один цвет для бордеров, но пока этот)».

Юзер также: «какой цвет у строука в темной теме?» — заметил что `--surface-2` в dark = `#0F151E` (почти чёрный) → border практически сливается с `--background` (тоже тёмным). А `--border` (`#BFC5D2` light / `#5A6678` dark) контрастен в обоих темах.

# Token semantics

- `--surface-1/-2/-3` — фоновые поверхности (карточки, секции, контейнеры). Не предназначены для границ.
- `--border` — единственный token для границ (пока). Может появиться `--border-strong` или подобный для эмфазы — спросить юзера.

# Что было исправлено в DS

2026-05-20 пакетная замена `border: ... solid var(--surface-2)` → `var(--border)` в:
- `sub-nav.css` + `.js`
- `list.css` + `.js`
- `header-s.css` + `.js`
- `header-l.css` + `.js`

# Как применять для новых компонентов

- При получении Figma-параметров с `border-bottom: 1px solid var(--surface-2)` → транслировать как `var(--border)` в код, не следуя слепо Figma. Figma может экспортировать surface tokens по ошибке.
- При новых правках — `border: ... solid var(--border)` сразу.
