# Генератор токенов из Figma

> Spacebridge DS — css/tokens.css генерируется из Figma; три режима раскладываются mobile-first

`css/tokens.css` больше НЕ правится руками — собирается из `Figma Tokens/*.json`:

```
jsc tools/gen-tokens.js              # перезаписать
jsc tools/gen-tokens.js -- --check   # только проверить (это же гоняют тесты)
```

**Главное открытие (04.08.2026):** у переменных Figma три режима — Desktop /
Tablet / Mobile — и 57 из них имеют разные значения. В код годами переносили
только Desktop, поэтому вся адаптивность, заложенная в макетах, не существовала:
на телефоне `gap-horiz-m` оставался 16 вместо 8, H1 — 96 вместо 64.

**Как устроено:** mobile-first. База в `:root` — мобильные значения, планшет и
десктоп добавляются `@media`-блоком в конце файла. **Компоненты не трогаются
вообще** — `var(--gap-horiz-m)` сам отдаёт нужное по ширине экрана. Это ответ на
вопрос юзера «неужели нельзя автоматизировать адаптивность» — можно, и он сам её
уже спроектировал в Figma.

**Брейкпоинты тоже из Figma:** `Screens/min-screen-width` = 320 / 768 / 1280.
Не выдумывать свои (я предложил 640/1024/1440 не заглянув в JSON — мимо).

**Карта имён — `tools/token-map.json`.** Имена в Figma и CSS различаются
(`Buttons/Primary & Text/Size/Min Width` → `--btn-primary-min-width`), плюс в
Figma есть опечатки (`Line-Hight`, `Max Wigth`). Не сопоставилось — генератор
ПАДАЕТ, а не угадывает. Дубли вроде `Padding/pad-horiz-16` и
`Status-Text/Padding/pad-horiz-16` разводятся картой.

**Гоча jsc:** флаг передавать как `jsc file.js -- --check` (без `--` jsc примет
его за свою опцию); `arguments` на top-level есть только при таком запуске.
Запустить процесс из jsc нельзя, поэтому генератор разделён на библиотеку и
main через флаг `GEN_TOKENS_LIB` — тесты зовут `sbTokensCheck()` после `load()`.

Цвета генератор НЕ трогает: они в `js/tokens.js` (COLOR_TOKENS) и переключаются
через `data-theme`. См. [figma-tokens-immutable](figma-tokens-immutable.md), [tests](tests.md).
