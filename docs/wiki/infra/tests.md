# Тесты на jsc

> Spacebridge DS — тесты на jsc: 23 проверки (было 19 — счёт растёт, актуальное число говорит сам прогон), что покрывают и чего принципиально НЕ ловят

Прогон (node в системе НЕТ, раннер на JavaScriptCore из macOS):

```
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc tests/run.js
```

Файлы: `tests/run.js` (раннер), `tests/static.js` (текстовые правила),
`tests/runtime.js` (загрузка + фабрики), `tests/lib/{harness,dom,allowlist}.js`.

**Покрыто (23 проверки, состояние на 09.2026):** догма Клементия как линтер (рукописные кнопки, hex/rgb,
инлайн svg, инлайн font-*), синхронность `COMP_CSS` с css-файлом, существование
токенов и иконок, порядок загрузки + `_index.js`, смоук всех 63 `sbMk*`,
отсутствие `undefined`/пустых кнопок, канон классов кнопки, баланс тегов.

**НЕ покрыто и не может быть:** всё layout-зависимое — sticky, `@container`,
overflow, computed styles. Баг «пустоты в сайдбаре» (невидимые sticky-хедеры)
не ловится ничем из этого. Зелёный прогон ≠ визуально корректно.

**Самая ценная проверка — «скрытые зависимости»:** бандл грузится ДВАЖДЫ, и если
секция при втором прогоне длиннее, значит при регистрации чужая фабрика ещё не
была загружена и guard `typeof sbMkX === 'function'` молча съел кусок доков.
Так нашлись мёртвые демо-композиции в Header S и Header M. См.
[script-load-order](../patterns/script-load-order.md).

**Гочи харнесса:** все файлы грузить ОДНИМ `eval` (иначе top-level `const` из
core.js невидим компонентам); пробники, которым нужны `SB_REGISTRY`/`SB_PG`,
исполнять ВНУТРИ бандла, а не снаружи.

Исключения из правил — только в `tests/lib/allowlist.js` и обязательно с причиной.
