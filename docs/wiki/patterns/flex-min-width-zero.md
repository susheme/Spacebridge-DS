# Flex: min-width 0

> Когда контент в flex-контейнере с overflow:hidden обрезается — фикс в min-width:0 на flex:1 ребёнке, не в локальных padding-хаках.

Если в flex-контейнере с `overflow: hidden` правый/левый слот «застревает» или обрезается при сужении — корень в `flex:1` ребёнке: у него default `min-width: auto`, который не даёт сжиматься ниже intrinsic content size (placeholder, текст и т.п.). Сумма flex-детей превышает ширину контейнера → overflow клипает соседей с `flex-shrink: 0`.

**Фикс:** `min-width: 0` на flex:1 ребёнке (на уровне компонента, не локально).

**Why:** конкретный кейс — Search Bar с `iconLeft + rightSlot` (KBS ⌘+K) в узком сайдбаре. Сначала пробовал локальный `padding-right: 24` для `.sidebar-search`, потом `min-width: 0` на самом баре — оба фикса не работали, потому что сжиматься надо было *input'у*, а не бару. Пользователь явно просит автоматическую адаптивность, а не локальные оверрайды.

**How to apply:** при любом «слот в flex-баре уезжает за rounded edge / клипается» — первым делом проверяй `min-width` у `flex: 1` ребёнка. Не маскируй padding'ами.
